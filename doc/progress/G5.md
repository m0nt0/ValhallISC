## Delivered
- `mount/adapter.py`: mfusepy `Operations` that delegate to `VirtualFS`. `FsError` becomes `FuseOSError`, and unexpected exceptions become `EIO`.
- `mount/worker.py`: the worker process.
  - It reads the start command, checks the login and the mount point, then mounts.
  - It emits `mounted`, `unmounted`, `error` (with codes), `imported` and `import_failed`.
  - `stop`, `stop` with force, and stdin EOF all unmount.
  - The real stdout is reserved for events; fd 1 is pointed at stderr.
- `mount/options.py`, `mount/unmount.py`, `mount/protocol.py`.
- CLI: `irisfs mount` (by profile or ad hoc, `--password-stdin`), `irisfs unmount [--force]`, `irisfs profiles`, `irisfs worker`.
- E2E harness: real worker subprocesses, and a TCP proxy that simulates IRIS outages (E2E-14).

## Findings fixed during the gate
1. **Performance:** the first run measured `ls -R` at 7.7 s. Fixed with a parallel size prefetch on `readdir` (ADR-006).
2. **Filter leak:** `EnsebXML*.inc` was visible in the default view. The `Enseb` prefix was added (ADR-003).
3. **Finder, reported by the user (screenshot):** the volume showed as "adhoc" and as a "Remote Volume", not in the sidebar. There were two bugs:
   - the worker didn't pass the mount folder to the option builder, so `volname` fell back to the profile name;
   - `ensure_loaded()` sets `FUSE_LIBRARY_PATH`, after which `find_library()` reported the kind as `"FUSE_LIBRARY_PATH"`, so the macFUSE-only options (`local`, `noappledouble`, `noapplexattr`) were silently dropped.

   Both are fixed, with regression tests (`test_worker.py`, `test_fuselib.py::test_kind_survives_env_set_by_ensure_loaded`).
   - Root cause of both: scripted text replacements that silently didn't match after reformatting. Edits now use a tool that fails on a mismatch.
   - The volume is now named after the mount folder and marked `local`. A virtual `/.metadata_never_index` keeps Spotlight from exporting the whole server.

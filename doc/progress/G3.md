## Delivered
- `atelier/client.py`: `AtelierClient`.
  - One shared `httpx.Client`, so the session cookie is reused. At most 4 requests run at once.
  - Retries: a connect error is retried once, and idempotent calls are retried once after a timeout. `xml/load` is never replayed.
  - Errors are typed (`AuthError`, `ForbiddenError`, `NotFoundError`, `ServerError`, `ConnectionFailed`, `UnsupportedServer`). IRIS status codes are mapped: 6308 → NotFound, 5883 → Forbidden.
  - Logs contain only the method, path, status and timing, never headers or bodies. A unit test checks this.
- `atelier/api.py`: the `AtelierApi` protocol, used by the VFS and implemented by the client and the fake.
- `tests/fakes/fake_atelier.py`: an in-memory fake with error injection.
- Contract suite (`tests/integration/test_atelier_contract.py`): 10 behaviours × {fake, real}, all green. That includes import → list → export → reimport → delete, routine name normalisation, compile errors reported but still imported, `-c` (no compile), bad XML rejected with nothing changed, not-found cases, and unicode.

## Deviations
- The planned "export equals `$SYSTEM.OBJ.Export`" comparison was verified once in spike S2 (ADR-002). The automated tests don't repeat it, because the Linux test container has no Docker CLI to call `iris session`. They check structure, unicode bytes, and completeness of the 1 MB class instead.
- A read-only user's import doesn't raise: IRIS returns HTTP 200 with `#5883` in the per-file status. It's reported as `ImportResult.error`, and the fake does the same.

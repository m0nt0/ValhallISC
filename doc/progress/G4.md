## Delivered (`src/irisfs/vfs/`)
- `pathmap`: document name ↔ path, in the isfs layout with an `.xml` suffix. It's a bijection, checked by a Hypothesis property test, and non-canonical paths are rejected.
- `filters`: the ADR-003 visibility rule.
- `xmlexport`: safe validation with defusedxml (no DTDs or entities). The root must be `<Export>` with at least one code item, and `<Global>` data is refused.
- `junk`: OS-generated files (`._*`, `.DS_Store`, `desktop.ini`, …), which live only in memory.
- `tree`: a tree per namespace, with a 10 s TTL and invalidation, optionally case-insensitive.
- `content`: an LRU export cache bounded by size, keyed by (ns, doc, ts), single-flight. Sizes survive eviction.
- `vfs.VirtualFS`: getattr, readdir, open, read, create, write, truncate, flush, release, and the refused and no-op operations.
  - Import happens on the last close, **only if the file is dirty**.
  - `flush` validates XML early, so `cp` reports `EIO`.
  - Ghost entries (60 s) cover files whose names don't match an imported document.
  - Read-only mode returns `EROFS`, and IRIS errors are mapped to errno values.

## Deviations and findings
- **ADR-003 corrected:** `upd` in `docnames` means *up to date* (compiled), not "updatable". The first filter would have hidden every user routine with a compile error. It now uses reserved-name prefixes (`%`, `Ens…`, `HIPAA_`) instead.
- The seed routine `Demo.Rtn2.mac` had an invalid label (labels can't contain dots). It's fixed, and the image was rebuilt.

## Bugs found and fixed during the gate
1. **Copying the same file in twice within 60 s failed with ENOENT.** `open(O_WRONLY)` on a ghost entry fell through to the server lookup. A ghost opened for writing now becomes a new write buffer. Regression tests were added.
2. **`ditto` (and Finder's copy engine) failed with "Permission denied".** They write a hidden temporary file (`.BC.T_xxxx`) and then rename it. Hidden temporary files are now in-memory scratch files, and renaming one to `*.xml` imports it (`EIO` if the XML is invalid). This also makes editors' atomic saves work. Visible non-XML names such as `notes.txt` are still refused. Regression tests were added.
3. Scratch handles now reference the scratch object instead of its path, so a file renamed while open keeps working.

4. **Finder drag-in failed with error -36 (reported by the user).** Finder creates the file, closes it *empty*, then reopens it to write. The empty close was imported (error "The file is empty") and the buffer dropped. An empty file is now never imported on close. It stays as a placeholder for 60 s (deletable, expires silently), and `flush` no longer validates empty content. Regression tests were added.
5. **Finder drag-in then failed with "you don't have permission" (reported by the user).** The macFUSE option `noapplexattr` makes the *kernel* refuse `com.apple.*` xattrs with EPERM, before our code runs. Finder copies quarantine, provenance and FinderInfo and aborts on the error, while `cp` ignores it. Removing the option fixed it: our no-op `setxattr` now accepts them. There's a unit test for the options and an e2e test (E2E-28b) that sets Finder's xattrs on a real mount.
6. **Flaky unit test on Linux:** a background prefetch thread sometimes consumed a failure the test had injected. The test now disables prefetch, and 5 consecutive Linux runs are green.
7. The adapter now logs every mutating FUSE operation at DEBUG level (`irisfs -v mount`). That trace is what diagnosed items 4 and 5.

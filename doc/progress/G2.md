## Delivered
- `config/profile.py`: the `Profile` dataclass. Field-level validation covers name, host, port, user, path prefix, compile flags and the per-OS mount point format. Serialisation ignores unknown keys.
- `config/store.py`: `ProfileStore`.
  - Atomic JSON writes (temporary file, fsync, `os.replace`), files created with mode 0600.
  - Case-insensitive unique names.
  - Active profiles can't be updated or deleted (`is_active` hook).
  - A corrupt file is backed up and the store starts empty with a warning. A file with a newer schema is refused and left untouched.
- `config/secrets.py`: the OS keyring when usable, with a fallback to a 0600 JSON file. The fail and null keyring backends count as not usable.
- `config/mountpoint.py`: the §2.7 rules for POSIX and Windows, testable through an injected `FsProbe`. Includes the Windows remove-and-recreate of an empty directory.

## Deviations
- `ProfileStore.list()` is named `profiles()` to avoid shadowing `list` in type annotations.
- Windows UNC paths (`\\server\share`) are rejected as mount points, because WinFsp needs a drive letter or a local path. A unit test caught this.
